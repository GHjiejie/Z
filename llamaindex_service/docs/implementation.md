## 与原方案的具体实现取舍

- **授权检索使用自定义 LlamaIndex BaseRetriever + SQLAlchemy/pgvector SQL。** 没有直接使用 PGVectorStore 的默认查询，便于在同一 SQL 中连接成员、ACL、活动版本与索引代次。LlamaIndex 仍承担文档/节点、摄取编排、检索器抽象、模型适配和问答组织。
- **向量检索当前使用精确排序。** 尚未加入 HNSW/IVFFlat；因此过滤后不会通过放宽权限补足候选，但不能据此承诺百万片段低延迟。
- **中文词法采用版本化的中文双字词项 + 拉丁词/技术标识符。** PostgreSQL 全文检索使用 OR 查询，名称不是 BM25；当前未引入语言学分词或训练出的稀疏检索模型。
- **模型桥接补充了真正异步的 Responses 文本/usage 处理。** 未改动共享 `chat_models/chat.py`。mock 模型使用独立 `mock:` 模型标识，避免测试向量误被真实模型配置接收。
- **上下文预算按保守 UTF-8 字节数计算。** 追问解析使用已授权历史用户问题辅助常见代词，不宣称复杂多跳查询改写。
- **引用校验只验证编号和授权来源映射。** 不自动证明每个事实受引用内容支持；真实质量评估仍需人工标注和抽检。
- **模型/维度切换采用维护窗口。** 完整影子索引可原子激活，但 API 需要配套更新配置；本版没有每库动态模型路由或无中断切换承诺。
- **旧版本引用采用保守处理。** 不再属于当前活动版本/代次的历史会话片段会被隐藏，授权用户仍可通过版本下载接口取回未删除的旧原文。

## 验证方式

最终执行 `RAG_TEST_DATABASE_URL=... uv run --group rag python -m unittest discover -s llamaindex_service/tests -q`：**113 项测试全部通过，无跳过**。Ruff 检查、格式检查、根目录 `uv lock --check` 与 Compose 配置解析均通过。HTTP 集成测试为每个用例创建独立临时 PostgreSQL 数据库，避免跨租户 Worker 合法领取其他用例的清理任务造成测试干扰；测试账号需具备 CREATEDB 权限，临时库结束后删除。

离线测试使用 SQLite 和显式模型替身验证可重复逻辑；PostgreSQL 测试使用独立测试库验证真实 pgvector、全文检索、RLS、运行角色、事务局部作用域、租约、发布与跨连接并发。HTTP 边界测试注入真正的 ASGI 断连事件，分别覆盖 JSON/SSE 与不同 ASGI 版本。

关键回归包括：越权 SQL 无正文泄漏；成员/文档权限撤销；提交时撤权不能输出成功答案；上传幂等冲突；流式中断取消上游；超限分块上传返回 413；版本发布失败保留旧版；过期 Worker 不得发布；模型配置错配拒绝；删除后新请求不召回；孤立文件回收不删除已引用对象。

现有聊天模型已通过无敏感信息的真实异步流式连接测试，但当前网关未提供 usage，实际返回 `usage:null`。使用含 usage 的测试响应验证过适配器会保留用量。没有调用未经配置的真实 Embedding 或 Reranker 端点。

Docker 镜像已成功构建，Linux 容器内的文件解析/存储测试通过。S3 测试使用协议替身，尚未连接真实 bucket。Compose 配置通过解析验证。

## 合成样例结果

使用真实 API、Worker、PostgreSQL/pgvector，搭配显式 mock 模型，数据为 4 份虚构文档、20 条合成问题。其中 16 条有答案、4 条无答案。完整报告位于本地 `evaluation/results/synthetic-smoke.json`（不提交生成文件），可提交摘要见 [评估说明](../evaluation/README.md)。

| 指标 | 结果 | 解释 |
| --- | --- | --- |
| 检索请求错误 | 0 | 仅证明流程稳定 |
| Recall@3 / MRR | 1.0 / 0.9375 | 小型合成语料、确定性测试向量 |
| 无答案正确率 | 25%（1/4） | mock 没有可靠语义拒答能力，不达到真实验收要求 |
| 并发探针 | 20 请求、并发 4，全部成功 | 进程内 ASGI 传输，不包含真实 HTTP 网络 |
| 成功请求 P95 | 42.267 ms | 4 份文档、64 维测试向量，不能推断生产 SLO |

最终又通过真实本地 HTTP 端口执行一次完整上传与查询：1536 维 mock、同样 4 份文档与 20 条问题，检索错误为 0，Recall@3/MRR 均为 1.0，无答案正确率仍为 25%。随后 100 请求、10 并发全部成功，检索 P95 为 267.33 ms。这些结果记录在 `evaluation/results/local-http-smoke.json` 与 `local-http-load.json`，仍只适用于该小型测试环境，不能替代真实模型或百万片段验收。

## 外部验收与明确边界

后端功能可以运行，但以下项目没有被替代测试证明完成：

1. 可用的真实 Embedding 模型、服务地址、凭据及企业数据外发规则；重排如启用也需要真实端点验证。
2. 至少 100 条真实业务问题的人工标注集；召回、事实支持率、引用正确率和无答案处理需以保留测试集验收。默认相似度阈值尚未校准。
3. 百万片段、10 并发、目标硬件上的检索与首 token 性能验收；当前精确检索可能需要后续索引优化。
4. 生产 JWT issuer、成员同步、独立数据库账号、私有对象存储、备份与恢复演练。
5. 现有聊天网关 usage 缺失；Embedding/Reranker 的调用成本计量也尚未集成商业计费。

OCR、飞书/Confluence 同步、管理前端、复杂表格/多模态、GraphRAG 属于原方案的后续范围。
