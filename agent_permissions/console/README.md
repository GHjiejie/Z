# Agent Console

Agent 会话与用户管理 UI，使用 React、TypeScript、Vite、Lucide 图标和原生 CSS，接入 [Agent Chat 接口](../docs/chat-api.md)及[用户管理接口契约](../docs/user-management-api.md)。助手回复使用 `react-markdown` 和 `remark-gfm` 渲染。

## 页面

| 页面 | 内容 |
| --- | --- |
| 登录 | 用户名与密码登录、错误反馈、会话失效提示 |
| 会话 | SSE 流式 Markdown 聊天、多轮上下文、新建与切换会话、草稿、删除记录、停止生成、复制回复、模型发现、工具参数卡片、执行确认、暂停恢复与错误恢复 |
| 用户管理 | 用户总数与账号统计、搜索、角色与状态筛选、排序、分页、新增、编辑、角色分配、Agent 工具授权、重置密码、启用、禁用、删除 |
| 角色与权限 | 可配置 RBAC：新增角色、编辑权限、查看分配人数、删除未使用自定义角色；内置管理员受保护 |
| 个人设置 | 个人资料、当前权限、本人密码修改 |

页面按当前有效权限显示：用户管理需要 `user.read`，角色管理需要 `role.read`，具体操作分别校验创建、更新、删除和角色分配权限。具有 Console 基础权限的登录用户可进入会话和个人设置；管理员默认进入用户管理，普通用户默认进入个人设置。前端根据当前权限呈现操作，实际授权仍由后端执行。

## 使用会话

业务工具需先在用户列表的“更多操作 → Agent 工具授权”中开启。新用户及升级后的用户默认未授权，包括管理员；普通聊天无需工具。配置按用户保存，缺少业务权限也可以预先开启，角色变化保留设置，实际执行继续受 RBAC 限制。查看需 `user.read`，编辑还需 `user.agent_tools.manage` 和目标管理范围，见[授权说明](../docs/user-agent-tool-grants.md)。

登录后点击导航中的“会话”，或直接打开 `/console/#chat`。页面读取 `GET /v1/models` 获取模型，使用当前业务登录令牌请求 `POST /api/v1/ag-ui`，以 `fetch` 读取标准 AG-UI 1.0 SSE 事件，类型与运行时校验使用官方 `@ag-ui/core`。Agent 自动执行参数完整的读取；需要补参或执行写操作时先显示参数确认卡片，模型供应商密钥只由服务端使用。协议和原生暂停恢复见 [AG-UI 说明](../docs/ag-ui.md)。

- 输入消息后按 Enter 发送，Shift + Enter 换行；中文输入法确认候选时不会误发送。生成期间可编辑下一条草稿，不能重复发送。
- 新建、切换、删除会话和离开页面会停止当前生成，已收到的内容会保留；停止生成不代表撤销已经执行的业务操作。
- 会话、草稿及模型选择保存在当前浏览器的 `localStorage`，以用户 ID 隔离，刷新后恢复。退出登录保留本账号历史；清除浏览器站点数据会删除记录，完整聊天历史不支持跨设备查看；持有本人任务标识时可使用“打开已有任务”读取有效期内的服务端任务。
- 正在生成的内容每约 300ms 保存一次，刷新后从服务端读取运行状态，恢复等待中的卡片或已收到的回复，不会自动重新发送。断流后先“读取最新任务状态”，需要时点击“恢复此任务”继续原图；“编辑原消息”只恢复输入框内容。
- 后续请求携带最近 60 个已完成轮次的文本。中断或失败的轮次保留在界面中，不自动加入后续请求，避免再次执行未确认结果的业务任务。
- 本地存储不可读时保留原记录，本次聊天使用内存；写入失败时显示提示，仍可继续聊天。需要保留的内容可复制保存。
- 会话列表与聊天区从主导航右侧开始铺满窗口，不显示外层 header、页面标题或页脚。会话切换、当前会话名称、工具状态和模型选择保留在聊天区内，账号资料和退出入口移至主导航底部（窄屏放在品牌旁）。消息和 HITL 表单在内容区内滚动，输入区保持可见。输入框默认单行，随内容增长，达到高度上限后在框内滚动。
- 阅读较早的消息时不会被新内容拉回底部，可点击“回到最新消息”。桌面可通过“会话记录”收起历史以扩大内容宽度；窄屏以浮层展开历史，选择会话或点击内容区后关闭。Escape 关闭历史并将焦点返回切换按钮。减少动态效果设置会关闭相关动画与过渡。
- 每条助手消息显示“执行过程”，包含真实模型步骤、公开返回的思考摘要、工具名称、调用参数与结果，以及等待确认、失败、中断等状态。工具声明与执行结果分开显示；模型没有提供思考摘要时明确提示。过程记录随任务和浏览器历史恢复，密码等秘密不进入过程记录。

会话页展示当前账号可用的业务工具数量（用户工具授权与当前 RBAC 的交集，不含登录工具）。工具为空时，页面说明只能普通聊天，无法触发参数表单或执行业务操作。授权统一在用户管理的“更多操作 → Agent 工具授权”中配置；返回会话页后重新读取可用数量，也可手动刷新工具状态。工具状态读取失败时可以重试，不影响普通聊天。

工具卡片从服务端 Schema 生成，支持文本、数字、枚举、角色/权限选项、目标搜索和密码。写入必须“确认执行”，只读补参为“提交并查询”。等待时关闭 SSE 并收起消息输入，给表单留出空间；同会话新消息需要先处理或取消待办。目标或工具版本冲突后只能主动“重新准备并核对参数”，不会自动重试写入。刷新丢弃未提交的表单编辑和秘密；密码不进入模型、浏览器持久存储或 checkpoint。具体边界和接口见[交互工具说明](../docs/agent-hitl.md)。

卡片按操作状态、参数填写、确认操作分区显示，操作对象单独展示。必填参数优先显示；可选参数集中折叠，已有建议值时自动展开，未启用的参数不显示空白输入框。角色和权限使用勾选列表，搜索、加载失败与重试仍通过原接口完成。表单按卡片实际宽度切换单列或双列，有效期和操作按钮集中在底栏。折叠字段校验失败时自动展开并定位，修改失败保留草稿；密码可临时切换可见性，提交和存储规则保持一致。

助手回复在生成过程中持续按 Markdown 渲染，支持标题、段落、强调、引用、列表、行内代码、代码块、链接及 GFM 表格、任务列表和删除线。尚未闭合的代码块会显示已收到的内容；代码块与表格可在容器内横向滚动。历史和复制保留原始 Markdown，刷新后重新渲染。用户输入保持文本展示。

Markdown 渲染忽略原始 HTML，沿用渲染库的 URL 协议过滤；外部链接在新标签页打开，并设置 `noopener noreferrer`。

## 启动

在本目录运行：

```bash
npm ci
npm run dev
```

访问 `http://127.0.0.1:5173/console/`。Vite 将 `/api`、`/v1`、`/docs` 和 `/openapi.json` 代理到本机 8000 端口的 FastAPI，`/v1` 同时承载模型发现和 SSE 聊天。后端启动和管理员初始化见[运行说明](../docs/running.md)。

生产构建：

```bash
npm run build
```

构建结果在 `dist/`。重新启动 FastAPI 后，可直接访问 `http://127.0.0.1:8000/console/`，无需额外运行前端服务。

## 状态与交互约定

- 会话令牌保存在当前标签页的 `sessionStorage`，页面刷新后重新核验用户。密码仅在表单提交时使用，不写入浏览器持久存储。
- 首次登录及管理员重置密码后均直接进入有权限的页面。用户可以在个人设置中主动修改密码，修改成功后重新登录。
- 收到 `401` 时清除失效会话并返回登录页；检测到权限变化或窗口重新获得焦点时，重新读取当前身份和权限。
- 已退出会话的延迟响应会被丢弃，不能覆盖新登录用户的信息或清除新会话。
- 列表请求使用取消信号，避免快速搜索或切换筛选时，旧响应覆盖最新查询结果。
- 编辑、角色、状态、删除、重置密码之前读取目标详情和最新 `ETag`，提交时携带 `If-Match`。
- 版本冲突时保留草稿，不自动重试写入。用户主动选择“载入最新信息”后，才使用最新值替换草稿。
- 表单提交期间禁用重复操作，错误时保留输入。列表区分加载、数据、空结果、失败和刷新失败时的旧结果。
- 弹窗使用原生 `dialog` 处理焦点约束，支持 Escape 取消与关闭后焦点恢复。操作菜单可使用方向键和 Escape。
- 用户输入通过 React 文本渲染；助手 Markdown 通过语法树转为 React 元素，不将接口内容直接注入 HTML。
- 日期显示为北京时间。窄屏使用横向导航和容器内表格滚动，避免整页横向溢出。

## 视觉规范与本轮打磨

本轮按“权限登记册”的方向做轻度打磨，保留 Agent Console 名称、原有蓝色品牌、系统字体和页面分区。视觉重点是成员身份、真实账号状态和角色允许的操作。

| 顺序 | 调整 |
| --- | --- |
| 1. 间距 | 使用 4px 间距节奏，控件内部允许 2px 微调；桌面导航为 36px 行高、4px 间隔，页面边距 32px，表格行高至少 72px |
| 2. 色彩 | 文字收敛为主文字、次文字和元信息三种颜色，蓝色用于主要动作与选中状态，绿色和红色表达实际状态与结果 |
| 3. 图标 | 统一 Lucide 16/18px、1.5 描边；移除统计卡装饰图标，头像采用统一中性色 |
| 4. 文案 | 登录标题改为“登录 Agent Console”，短提示使用具体动作和状态，删除短句末尾的冗余句号 |
| 5. 字级 | 正文 14px，说明和元信息 12px；页面标题 28px，统计数字 32px；使用 400/500 字重，品牌保留 600 |
| 6. 布局 | 保留侧栏、统计、筛选和列表顺序，统一对齐与内容内边距；窄屏筛选分行，表格在容器内横向滚动 |
| 7. 细节 | 控件圆角 8px、卡片 12px、弹窗 16px；表头、普通行、悬停和键盘焦点可辨识，计数保持普通数字文本 |
| 8. 视觉 | 保留并对齐登录页现有“身份→角色→权限”示意，只在账号启停状态保留语义圆点；界面以真实数据为视觉重心 |
| 9. 动效 | 悬停反馈与菜单使用统一 160ms 曲线，菜单仅移动 4px；减少动态效果时移除过渡和动画，加载反馈仍有文字说明 |

静态配色核对：元信息在白色、页面、次级表面和选中背景上的对比度分别约为 5.23:1、4.91:1、4.78:1 和 4.69:1；白字与主要蓝色按钮约为 4.98:1。此处是所用配色的检查结果，不代表完成了整站无障碍认证。

方法参考 [unslop](https://heydamir.design/unslop)，作者 Damir Sokolovsky（[@heydamir](https://x.com/heydamir)），遵循 CC BY 4.0 署名要求。样式源码保留对应说明。

## 验证

```bash
npm run typecheck
npm run format:check
npx playwright install chromium
npm run test:e2e
```

Playwright 使用真实 FastAPI 和临时 SQLite；Agent 使用测试模型，不访问供应商。SSE 测试服务真实分段发送数据，覆盖 UTF-8 拆包、流式 Markdown、未闭合代码块、原文复制、HTML 与链接处理、停止、错误、断流、上下文、历史恢复、账号隔离、中文输入法及阅读位置。测试数据只存在于临时数据库中，服务退出后自动清理；浏览器错误追踪和截图保存在忽略提交的 `test-results/`。
