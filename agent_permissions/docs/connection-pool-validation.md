# PostgreSQL 连接池验证报告

- 验证日期：2026-11-13。
- 范围：`agent_permissions`，按[连接池方案](connection-pool-plan.md)实施。
- 环境：仓库根 Python 环境，Psycopg `3.3.6`、psycopg-pool `3.3.3`、FastAPI `0.141.1`；本机 Docker PostgreSQL `18.6`。
- 测试与压测使用单独创建的测试数据库，每个用例或模式使用随机 schema；故障测试只终止测试池自己的 backend。未重启业务数据库或改写业务账号。

## 实现结果

PostgreSQL 每个 API worker 独立开池，构造适配器时没有网络操作。FastAPI lifespan 显式开池、等待预热、初始化，并在正常退出和启动失败时关池。管理员和迁移 CLI 也负责关闭自己创建的池；显式重新打开适配器会建立新池。SQLite 继续使用短连接。

默认最小 2、最大 10 条连接，借用等待 3 秒、队列最多 20 人。完整参数见[运行说明](docker-database.md#postgresql-连接池)。连接保留 `autocommit=True`、元组行格式、DSN `options`、10 秒建连超时及 `application_name=agent-users`。读事务只读 `REPEATABLE READ`，写事务在鉴权读取前取得原 advisory lock；锁和 SQL 的事务局部超时保持 10 秒、30 秒。

每次借用统一清理游标，异常回滚或清理失败时丢弃不可靠连接，保留主要异常。池超时、队列满、池关闭和连接不可用返回脱敏 503，跳过失败审计的二次借用。普通业务拒绝仍写独立失败审计，成功修改和审计仍在同一事务。写入提交结果不确定时不自动重放。

内部 `pool_stats()` 使用累计快照，不清空计数；故障日志按请求、worker 和池指标关联。驱动后台日志仅保留安全事件类别，故障注入验证了 URL、密码和诊断原文不会进入响应或日志。未增加公开池状态接口。

## 本机运行验证

排空并停止原短连接 API 后，使用相同私有 `.env` 和原 PostgreSQL 数据库重启了本机 8000 端口服务。重启前完成一次 `admin / 12345` 登录，重启后继续使用同一会话请求个人信息、用户列表和角色列表，均返回 200；验证结束后正常退出该测试会话。

启动前后对 8 张应用表逐表检查行数与规范化内容摘要，全部一致，未重新初始化管理员或导入数据。查询 `pg_stat_activity` 观察到 API 预热的 2 条连接；顺序执行 20 次用户查询后 backend PID 集合保持相同，两条连接均恢复 `idle`。Console 和 Swagger 入口均返回 200。业务数据库及 Docker volume 保留，测试专用数据库在验证结束后清理。

## 本地对比压测

采用同一个 PostgreSQL 实例、同样的管理员与 40 名成员数据、同样的业务代码和单 worker，通过 FastAPI `TestClient` 并发调用接口。短连接基线仅将适配器的连接获取替换为每事务新建、关闭 `psycopg.connect()`；它是受控对比模式，没有运行两套独立部署。

读负载为 `GET /api/v1/users`，每页 10 条；混合负载为 90% 同类查询、10% 用户资料 `PATCH`。各并发执行器修改不同的目标用户，并按返回值更新 `If-Match`，保留真实鉴权、审计和全局写锁。登录与数据准备不计入测量，每个场景先执行 20 次预热请求。

连接池使用默认最小 2、最大 10、等待 3 秒、队列 20；同一模式连续执行全部场景，池增长后继续复用。并发 1 和 10 每场景 160 次请求，并发 20 为 200 次，并发 40 为 400 次。统计采样间隔约 2ms；建连列为测量期增量，不含预热。池的“连接峰值”是管理容量采样，基线为同时打开的物理连接采样；两者用于观察上限，不代表相同的瞬时执行量。

这次测量中，预热后顺序 160 次查询的物理建连从 160 次降为 0；10 并发查询全部成功，P95 从 184.43ms 降至 29.70ms。连接池在全部场景中管理容量最多 10，等待者最多 20，验证了复用与配置边界。

40 并发读请求的 503 比例为 **40.75%**，混合请求为 **42.00%**；按测得用时计算，成功吞吐约为 **400 RPS** 和 **262 RPS**。这一结果表明默认队列在该负载下已满，不能认为默认参数支持 40 个请求同时无损通过。生产调参应先确定可接受失败率和延迟，再核对 worker、线程池、写锁和数据库预算；不能只增大连接池。

这是本机一次短时测量，通过进程内 TestClient 调用，未覆盖外部 HTTP 网络、长时间稳态、跨机器延迟或生产数据规模，也没有重复试验置信区间。40 并发的延迟分位数混合了成功与拒绝响应，不用于判断成功请求的延迟目标。当前收益结论仅限这组受控条件；生产容量需要在目标环境另行压测。
