# 真实执行评测与生产门禁

平台 Schema 7 增加不可变评测集、项目级发布策略、评测证据和治理审计。原来固定返回 `PASSED / 0.94` 的接口已经移除。现在的分数由服务端读取真实 Run 后计算，客户端不能提交分数、状态或执行证据。

## 使用流程

1. 管理员调用 `POST /api/v1/evaluation-suites` 创建不可变用例集。修改用例必须创建新集，不能覆盖历史内容。
2. 为候选 Revision 创建 development/staging 部署。按用例输入分别创建 Thread / Run，每个用例使用独立 Run，必须在用例集冻结之后执行。
3. 正常等待执行结果；涉及审批与恢复时，通过原审批 API 完成人工决策，不接受模型自行声称批准或恢复。
4. 调用 `POST /api/v1/agent-revisions/{revision_id}:evaluate`，提供 `suite_id` 和 `case_runs`（用例 ID 到 Run ID 的映射）。必须覆盖全部用例，不能用一个 Run 冒充多个用例。请求可带 `Idempotency-Key`；同一键更换请求内容返回 409。
5. 通过 `GET /api/v1/evaluations/{evaluation_id}` 查看分项判定、实际证据摘要、分数及 `production_eligible`。`PASSED` 只表示该评测集的断言通过，不等于整个系统已完成生产验收。
6. 管理员使用 `PUT /api/v1/evaluation-policy` 指定发布必须使用的评测集。首次提交 `version: 0`，以后使用服务端返回的版本；变更必须说明原因。有效期以秒计，默认一天，范围一分钟到七天。
7. 创建 production 部署时检查当前策略、同一 Revision / Plan / Suite 的最新结果。通过后部署保存 `evaluation_id`，治理审计保存结果摘要和策略版本。已有生产部署的新 Run 也必须重新通过门禁，不能利用旧部署记录绕过新的失败结果。

本阶段不自动创建、批准、取消或重试测试 Run。测试执行仍通过现有运行和审批接口完成；自动样本编排、前端评测工作台与 CI 触发器尚待补齐。等待审批的安全样本由测试负责人后续取消或处理。

## 用例与判定

每个用例包含 `id`、`category`、完整 `input`、`expected_status`，以及输出包含/不包含文本、必需事件、费用或耗时上限等断言。`expected_decisions` 固定审批决定的顺序、类型、编辑参数及消息，例如恢复用例可声明 `[{"type":"approve"}]`。字段采用严格校验，未知字段被拒绝。

当前版本验证单条输入及声明过的审批流程；存在后续用户输入或未声明的审批编辑时不能通过。`resume_input` 已设为服务端保留 metadata 字段，不能由客户端注入。完整多轮用例编排仍待后续实现。

生产发布策略至少覆盖以下四类；同一类别可以包含多个用例。除安全边界用例外，必需类别至少包含一个预期成功的正向样本，不能仅用预期失败的负向用例代替正常能力验收。

| 类别 | 服务端强制检查 |
| --- | --- |
| functional | 状态及正向输出断言，成功输出不得为空 |
| safety | 真实事件中出现审批边界 `interrupt.created` |
| recovery | 实际出现 `graph.resumed`，且有 `run.resumed` 或 `run.orphaned` |
| cost | 存在模型用量记录，费用在用例明确指定的上限内 |
| knowledge | 对绑定知识库的 Agent 必需；实际检索审计命中预期文档，输出包含 Citation |
| coding | 对 Coding Agent 必需；源码归档 SHA-256 匹配用例，平台验证报告非空且通过 |

一个用例的全部检查通过才计为通过，分数为通过用例数 / 总用例数。所有用例通过才能得到 `PASSED`。费用包含未结算预占；即使普通断言通过，存在未结算模型用量也不能作为生产证据。

基础恢复用例不能替代图检查点与工作区一致性、网络分区或完整灾备演练；文本断言和 Citation 检查也不能替代完整的语义正确性、召回率、统计采样和红队评测。评测集应由项目负责人按照业务持续扩充。

## 证据和并发契约

- 只接受同一租户、项目和目标执行计划的 Run；输入必须与用例完全一致。
- 只在 Run 终态或等待审批的稳定边界取样。读取时锁定 Run，冻结 Attempt、输入/输出摘要、完整事件边界、用量摘要、验证与知识检索证据。
- 评测按 Revision 分配单调序号，最新失败结果会阻止使用旧的通过结果发布。
- 生产证据同时检查评测时间和原始样本执行时间。重新评判旧 Run 不能延长样本有效期。
- 测试网关、Fake Sandbox、旧版模拟事件、模型身份与计划不一致、未验证用量和缺少覆盖类别均不能授予生产资格。
- 评测集与结果使用 SHA-256 检测内容变化；这不是对数据库管理员的防篡改保证，外部只追加审计归档与最小数据库写权限仍属于后续运维加固。
- 套件管理权限为 `evaluation.manage`，默认仅管理员角色拥有；普通发布人员可以执行评测但不能修改门禁。策略更新采用原子版本检查。

## 普通执行器的真实性边界

普通模型/RAG 执行器不再生成虚假的 SubAgent 进度、完成事件和固定待办，也不再将它们计入用量。尚未实现的 SubAgent 绑定会产生明确的 `runtime.capability.unavailable` 事件，该类计划不能获取生产评测资格。真正的通用 SubAgent 工具循环仍需后续实现，Coding Agent 的原生循环不受此限制。

审批通过的 `artifact_write` 现在只代表平台产物落库。产物、完成事件、用量统计与 Run 完成状态在同一事务内提交；模型或产物写入失败时不能发出完成记录。产物名遵循批准的 `/artifacts/*.md` 逻辑路径，不会执行外部发布、宿主文件写入或部署。

## 验证范围

`tests/test_evaluations.py` 使用受控提供方验证实际 Run → 审批恢复 → 评测 → 发布门禁，覆盖缺失策略、伪造请求、模拟证据、篡改、过期、旧样本重评分、错误输入/Plan、最新回归失败和权限隔离。

`tests/test_runtime_concurrency.py` 在 SQLite 与独立 PostgreSQL Schema 中验证策略更新竞争、评测幂等和非整数分数的证据一致性。这里的受控提供方用于验证服务端逻辑，不是对真实模型服务、生产部署或完整评测集的验收声明。
