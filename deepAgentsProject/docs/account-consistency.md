# 账号变更、会话与审计的一致性

## 生效边界

用户创建、资料/权限修改、管理员重置密码、自助改密、停用、单会话撤销、全部会话撤销和退出登录，均在同一数据库事务内完成业务写入和成功审计。需要撤销会话的操作也在这个事务中撤销，不能先提交新密码或权限再撤销旧会话。

审计或会话撤销失败时，整次变更回滚，用户版本不增加。调用者应读取最新状态后重试；网络在提交后中断的情形仍需以服务器状态为准，事务并不提供网络响应的 exactly-once 交付。现有乐观版本检查继续有效。

登录成功的会话、登录元数据、失败计数清理及审计也一起提交。错误密码、账号锁定、登录限流等预期拒绝在提交拒绝审计和失败计数后才返回认证错误；不可把所有异常都自动提交。数据库或审计写入异常会回滚整次登录，不签发可用会话。

## 撤权与并发

- PostgreSQL 在变更前按固定 ID 顺序锁定操作者和目标用户；所有会话写入采用先用户、后会话的锁顺序。SQLite 使用写事务覆盖整个操作。
- 事务内重新读取操作者账号、会话有效期、撤销状态、角色、超级管理员身份、密码更新要求与所属范围。不能沿用请求进入时已过期或被撤销的管理员快照。
- 登录同样持有目标用户锁。若登录先完成，随后重置密码会撤销刚签发的会话；若重置先完成，后来的登录必须验证新密码。
- 登录限流按请求键序列化；不同 IP 对同一账号的失败计数通过用户锁串行更新。不存在的账号也有共享限流键，不依赖进程内锁。
- 用户名、角色、超级管理员身份、租户、项目、环境或启停状态实际发生变化时，撤销该用户全部旧会话，包括操作者自己的会话。用户需要重新登录，旧令牌不会静默获得新的范围或权限。仅修改显示名称不撤销会话。
- 自助改密保留当前会话，撤销其他会话；管理员重置他人密码撤销目标全部会话。管理员重置自己的密码保留当前会话，但要求继续完成强制改密。

## 兼容性与接口

账号事务批次不增加 Schema，不需要本批专用数据迁移；当前应用 Schema 以迁移实现为准。不会补造历史上缺失的审计，也不会在升级时批量撤销现有会话。现有用户 API 路径和成功响应保持不变；`PATCH /users/{id}` 允许省略字段，但显式传入 `null` 返回校验错误。SQLite/PostgreSQL 的用户名唯一冲突均返回既有的 `409` 领域错误。

内置管理员启动初始化采用独立事务和跨进程锁；并发启动只能创建一个账号。已有管理员需要修复内置身份或首次改密状态时写入 `BOOTSTRAP_ADMIN_REPAIRED` 审计，不覆盖已经修改的密码。

服务层不带操作者的 `create_user` 仅供受信启动初始化/测试调用，HTTP 创建接口仍必须通过登录、强制改密和管理员权限检查。不得将这个内部入口作为匿名注册接口公开。

## 验证与未完成事项

计费、模型、评测及部分控制面写入已进一步复用账号锁并在事务中重新授权，覆盖撤权后仍在途的旧请求；准确入口和剩余外部 IO 边界见 [管理写入一致性](management-write-consistency.md)。

`tests/test_auth_atomicity.py` 使用临时 SQLite 数据库和随机独立 PostgreSQL Schema，覆盖审计写入前后故障、部分会话撤销后故障、拒绝证据、双连接修改竞争、登录与改密的两种顺序、撤权后的旧请求、启动竞争及重复用户名。测试不操作现有业务账号。

本批完整非 Docker 回归为 560 passed、3 skipped、5 deselected（396.26 秒），包含上述测试和原账号/权限/发布/执行/知识链路；真实 Docker 用例未执行。准确环境与其他待验收项见 `enterprise-hardening-status.md`。

事务内审计保证业务状态和审计记录一起落库，不等于防止数据库管理员篡改，也不替代外部只追加审计归档。SSO/MFA、企业组织成员模型、全平台长任务撤权验收、审计保留/导出和生产灾备仍属于整体企业化改造的后续工作。
