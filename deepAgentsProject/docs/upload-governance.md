# 上传、扫描与摄取容量（Schema 20）

本批补齐的是文档上传意图、逻辑保留字节和摄取执行的资源边界。它不代表全部企业化改造完成，也不声称已经限制或核实 OSS 全部历史版本产生的账单。

## 完成接口和隔离语义

`POST /knowledge-document-versions/{id}:complete` 先在当前账号权限下检查摄取容量，再进行有并发上限的对象 HEAD 检查。只有 bucket/key、固定 VersionId、声明大小、类型及可选 ETag 一致时，才在第二个事务中重新核验账号、文档权限、容量及版本状态，并原子写入对象引用、摄取任务、发起人、事件和队列投递。

完整对象下载及病毒扫描已从 API 移除。Worker 原子领取任务后读取固定版本，依次验证长度、SHA-256、安全扫描、受隔离解析、Embedding 和索引发布。每次实际摄取 Attempt 只做一次下载和扫描；同一任务的重复投递不能并发领取。崩溃后的新 Attempt 可以重新读取/扫描同一固定版本，不能将此描述为外部操作的 exactly-once 保证。

202 仅表示持久化接受校验，不表示文件已经安全。恶意文件在任务中变为 FAILED，不能产生索引或下载授权。前端继续展示任务阶段及失败信息。完成请求绑定发起人、范围和不可变文档版本；重放可以省略已验证的可选 ETag/VersionId，但不能替换已接受的来源。已有版本的下载仍要求 READY 及已发布的内容摘要。

## 额度与并发

以下配置在 API 和所有 Worker 上须一致；进程启动时读取。零额度表示拒绝新工作。生产应依据真实文档大小、容器内存、扫描吞吐和租户数量调整，不应把默认值视为已通过容量验收。

| 配置后缀（统一前缀 `DEEPAGENT_UPLOAD_`） | 默认值 | 含义 |
| --- | --- | --- |
| TENANT_BYTES / PROJECT_BYTES / USER_BYTES | 10 / 5 / 1 GiB | 已声明或保留的逻辑文档字节 |
| TENANT_PENDING / PROJECT_PENDING / USER_PENDING | 1000 / 200 / 50 | 尚未过期的待完成上传意图 |
| GLOBAL_RUNNING / TENANT_RUNNING / PROJECT_RUNNING / USER_RUNNING | 8 / 4 / 2 / 2 | 持有摄取执行状态的任务数量 |
| METADATA_PER_PROCESS | 8 | 单个 API 实例同时进行的对象 HEAD 数；满额立即 429 |
| PENDING_SECONDS / GRANT_SECONDS | 86400 / 900 | 意图期限及单次上传授权最长秒数 |

创建上传意图时，在租户事务锁下计算占用和插入业务行；幂等重放不重复预占。并发创建不能越过租户、项目或用户额度。没有成功提交的创建不会留下占用或幂等记录。

摄取领取使用 PostgreSQL 事务锁 `726593927603` 串行检查全局及范围内的 RUNNING 数量，然后原子更新任务/租约。满额任务保持 QUEUED，由已有持久恢复循环再次投递。过期但尚未被恢复器处理的 RUNNING 仍占位；完成/失败释放执行槽位。该指标约束有效任务状态，不冒充网络分区时对旧进程物理资源的绝对控制；容器内存/进程上限与宿主机故障隔离仍然必要。

普通关闭会保留正在执行的原生下载/扫描线程的所有权，等待其真正结束后才退出；不会把取消 `asyncio.to_thread` 当成线程已停止。下载有 100 MiB 内容上限、60 秒总时间检查及 SDK 连接/读取超时；ClamAV 使用总截止时间，慢响应不能反复延长超时。失败/超时关闭响应体和扫描连接。操作系统无法中断的故障及硬退出仍须由部署监督处理。

## 授权大小与期限

OSS PUT 授权将准确 Content-Length 纳入 V4 签名，服务端还检查生成 URL 的附加签名头。锁定版本 SDK 的 Config.additional_headers 未传入 SigningContext，因此使用其 signer 扩展明确绑定该字段；测试调用真实 SDK 和合成凭据，不通过伪造签名结果获得通过。

浏览器不能手动设置 Content-Length。控制台先校验文件长度与授权一致，再由 File 请求体让浏览器生成该头，继续发送其余签名必需头。真实浏览器到 OSS 的 CORS/代理/HTTP 协议链路仍需部署验收，不能把本机 SDK 和辅助函数测试当作真实 OSS 上传成功。

上传意图到期后拒绝续签和首次完成；恢复循环每批最多将 100 份过期意图标为 EXPIRED。已进入校验的任务不因旧授权到期而删除。控制台重遇 EXPIRED 意图时清除这次重试键并提示重新选择文件，不自动创建另一份副本。

## 不释放尚未确认删除的字节

逻辑保留字节包含 READY、FAILED、EXPIRED 和 PENDING_UPLOAD。过期只释放“待上传数量”占位，**不删除对象，也不返还保留字节额度**。这避免把未知或仍存在的对象误报成已回收。完整的引用感知删除、遗留对象核对和物理存储账单治理仍待后续数据生命周期批次实现。

OSS 签名 URL 在有效期内可重复使用；版本化 bucket 可能生成额外历史版本。准确 Content-Length 限制每次请求体，不限制请求次数或所有版本总容量。[OSS 签名 URL 官方说明](https://www.alibabacloud.com/help/en/oss/developer-reference/upload-an-object-using-a-signed-url-generated-with-oss-sdk-for-go)。生产仍需对象版本盘点、保留/清理策略及供应商侧流量/费用监控，不能将本批逻辑额度宣称为物理存储硬配额。

## 升级与验收

- 独立迁移新增版本表的 upload_expires_at、upload_request_hash 和容量索引。旧待上传记录只在迁移时获得一次 24 小时窗口，重启不续期；既有任务及固定版本引用保留。
- 新旧 API/Worker 不应混跑：旧 API 仍会重复扫描，旧 Worker 也不遵守新的领取上限。生产使用维护窗口统一升级；本批未执行业务库迁移。
- 备份仍使用已经固定的对象 VersionId；尚无固定对象的 EXPIRED 记录与未完成上传一样只备份元数据。隔离恢复不自动恢复上传授权或执行旧任务。
- 本机专项包含 SQLite、独立 PostgreSQL、多连接竞争、实际 SDK 签名、取消后线程所有权、失败文件隔离和前端签名长度处理。完整平台、Docker、Linux 和外部依赖验收必须分别记录，不能互相替代。
