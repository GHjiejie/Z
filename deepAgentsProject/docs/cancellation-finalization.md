# 取消收尾契约（Schema 18）

Coding 取消不再依靠旧执行器的异常处理生成产物。原执行租约立即撤销；平台通过单独的持久收尾记录停止沙箱、捕获差异和归档、发布产物，全部完成后才进入 `CANCELLED`。普通非 Coding Run 保持原有取消流程。

## 状态与重试

- `run_cancellations` 每个 Run 一条记录，绑定取消时的 Attempt、Workspace、Sandbox Instance 和工作区代次。Run 保持 `CANCELLING` 时 Thread 不接受新 Run。
- 收尾状态为 `PENDING → RUNNING → COMPLETED`。领取使用数据库事务及 Run 行锁；收尾租约 30 秒，处理期间每 10 秒续期。进程死亡后，过期记录可由其他 Worker 领取。
- 单次尝试的处理超时为 120 秒。外部不可取消 IO 会先排空，不把客户端超时冒充实际停止。失败按 2～60 秒退避重试，不清空原始文件，不误报成功。
- 失败原因仅记录异常类别，不将可能含凭据的外部异常正文写入事件。API 返回收尾状态、尝试次数和安全错误码，不返回租约令牌。
- 丢失沙箱、归档不安全、容量超限、扫描/存储不可用时保持取消中并提示自动重试。此处采取失败关闭策略；运维必须修复依赖或处理被拒绝的数据，不会为了放行新任务伪造完整产物。告警和运维处置控制台仍属于后续整体治理工作。
- 没有发布过可执行沙箱的取消不虚构补丁，记录 `no_workspace`。创建沙箱的迟到结果若无法提交，按本次创建的确切 ID 回收，不操作其他容器。

## 权限与沙箱隔离

`CancellationWriteFence` 与普通执行租约不同。它只在当前 Run 仍为取消中、原执行租约为空、收尾所有权和工作区代次匹配时允许提交。

远程沙箱新增固定 `POST /v1/sandboxes/{id}/cancel-capture`，只接受专用取消凭据。服务端通过只读 `sandbox_cancellation_leases` 视图验证准入、完成及执行期间的有效性。普通执行凭据不能调用此接口，取消凭据也不能调用任意命令、上传或恢复接口。

固定收尾只计算 Git 差异和文件摘要，不运行模型、项目测试或用户提供的命令。临时 Git index/object 由平台创建并清理，忽略可被 Agent 修改的全局 Git 配置和 fsmonitor/hook 设置。原 `.git` 仍只读；操作在执行容器内完成，不在 API/Worker 宿主机运行源代码。

归档覆盖仓库、产物和临时文件，仍拒绝链接、设备和目录穿越；文件摘要与同次冻结归档核对。不将截断的 Git 输出作为完整补丁。

## 原子产物与下一次任务

文件先扫描并写入内容寻址/版本化存储，再在一次受收尾租约保护的事务中提交：

1. 工作区快照及事件。
2. `PARTIAL` 验证报告、`REVIEW_REQUIRED` ChangeSet、文本/二进制补丁和差异清单。
3. 命令日志、摘要以及显式的取消恢复标记。
4. 收尾完成状态。

任何一步失败，以上数据库记录全部回滚，重试不会发布半套产物。未引用的已上传对象可能留下，后续引用感知 GC 需要处理；此功能不声称已经实现全平台对象回收。

取消恢复标记包含受摘要保护的文件归档和明确的空终止图，不读取旧执行器可能未完成的 checkpoint。新 Run 恢复文件并创建新的图会话，不重放已取消的命令。它不能用于恢复同一个已取消 Run。界面及验证接口都显示 `PARTIAL`，不沿用旧的 `PASSED` 作为取消后文件的验证结果。

## 升级和验证边界

- 使用独立迁移任务升级到 Schema 18；为沙箱只读身份额外授予 `sandbox_cancellation_leases` 的 `SELECT`，保留已有执行视图授权，禁止基础表读写。
- 在维护窗口停止新任务准入、排空旧 Worker，再迁移并统一替换 API/Worker/Sandbox Service。不能混跑会直接提交 `CANCELLED` 的旧取消执行器与新版收尾流程。
- 已经取消的历史 Run 不自动补造产物；旧数据缺失须显式处理，迁移不会猜测或覆盖历史证据。
- 本地真实 Docker 和 SQLite/PostgreSQL 契约测试不等于目标生产 Linux、真实 mTLS、OSS 和扫描服务组合验收。实际成绩见企业化实施状态。
