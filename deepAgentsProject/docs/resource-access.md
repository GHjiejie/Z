# 资源权限与知识元数据

## 会话与知识派生内容

账号在每次访问和后台执行时重新校验。Thread 默认私有；只有创建者可显式分享给本项目同环境成员。运行、事件流、工作区、产物及后续轮次还必须同时满足已经使用的每个知识来源的历史冻结权限和当前权限。管理员没有隐式的私有内容读取权。授权撤销后，已有游标不能继续取得被撤销的数据。

## 知识任务与事件

- 导入任务详情必须通过其文档的当前权限检查；不能只匹配租户/项目。内部服务调用也重新检查账号和 `knowledge.read`。
- 对外任务只提供状态、阶段、次数、分块数、错误及时间等明确列出的字段，不返回 Worker、租约、心跳、发起人角色快照。
- 文档关联事件通过其版本与任务引用找到文档，再校验权限。双引用不一致、引用缺失或未知事件类型按不可见处理。
- 事件先按权限过滤，再分页；被隐藏的新事件不会挤掉可见结果，也不会进入公共游标。返回前重新校验权限。
- 查询完成事件仅发起人可见。Schema 14 为新事件记录发起人，历史无法归属的查询事件不做猜测，保持隐藏。
- 知识库文档计数只包含当前用户能看到的文档。公共版本元数据不返回包含私有文档/分块标识的完整 manifest；内部编译和完整性验证仍读取原始不可变索引。
- 文档版本响应使用白名单，不暴露对象存储内部位置和运行控制字段。下载仍须通过文档权限与 READY/扫描状态检查。

知识库名称与版本发布状态目前是项目内共享元数据；文档内容、文档级导入状态与检索活动不会因此共享。如果企业要求知识库本身也有独立成员 ACL，需在组织/资源治理阶段继续补齐。

## 验证与升级

Schema 14 新增 `knowledge_events.actor_user_id`，不删除历史记录。API 的 `items` 兼容保留，知识事件响应新增 `has_more`/`next_cursor`；旧客户端若读取内部字段或完整 manifest 必须调整。

隔离测试覆盖私有文档不可通过任务/事件发现、活动租约字段不外传、角色撤销、跨项目访问拒绝、查询事件归属、隐藏事件跨批分页及游标不能跨用户复用。验证使用临时 SQLite/PostgreSQL 数据，不修改业务账号或文档。
