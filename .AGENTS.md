# Repository agent instructions

## Scope

These instructions apply to the whole repository. A more deeply nested `AGENTS.md` may add narrower rules for its directory.

## Repository overview

- This is a Python 3.13+ collection of LangGraph, LangChain, and Deep Agents examples.
- Most top-level directories are independent demos rather than one deployable application.
- `chat_models/chat.py` contains the shared chat-model setup used by model-backed examples.
- `subgraph_*` directories demonstrate graph composition and usually include a design document, Mermaid graph, and tests.
- `checkpoint_project/`, `interleave/`, and the frontend folders contain larger, self-contained examples; avoid assuming conventions from one demo apply to all others.

## Working conventions

- Use `uv` for dependency and command execution. Keep `pyproject.toml` and `uv.lock` consistent; do not hand-edit the lockfile.
- Follow existing Python style: four-space indentation, type hints for new public functions, small composable graph nodes, and clear docstrings where behavior is non-obvious.
- Preserve the public behavior of existing demos unless the task explicitly requests a behavior change.
- Keep deterministic examples offline. Use the existing simulated services or test doubles instead of adding network or model calls to a demo whose purpose is graph execution semantics.
- When a task needs a chat model, use the repository's configured `chat_models.chat.chat_model` and keep credentials/configuration outside source control.
- For any model-backed streaming path, call the LangGraph/agent streaming API with `version="v3"` (for example, `graph.stream(..., version="v3")`, `graph.astream(..., version="v3")`, or `graph.stream_events(..., version="v3")`). This `version` belongs to the streaming API; it is not an argument to `chat_model.invoke()`.
- Keep `version="v3"` consistent across nested subgraph/event-stream consumers. Existing `v2` demos are historical protocol examples and should only be migrated when the task explicitly asks for it.
- For LangGraph changes, make state boundaries explicit. Reducer-backed fields are required when multiple concurrent branches write to the same key; do not casually add last-value fields to fan-out branches.
- Keep diagrams in Markdown as fenced `mermaid` blocks when they explain architecture, state, or event flow. Update the nearby design document when changing graph topology or state contracts.

## Validation

Run focused checks for the code you change, for example:

```bash
uv run python -m unittest subgraph_concurrent_demo.test_demo -v
uv run ruff check .
uv run ruff format --check .
```

If a full-repository check is not practical because demos have optional runtime requirements, report the exact command and limitation. For documentation-only changes, at minimum verify Markdown fences, links, and any referenced paths.

## Safety and delivery

- Do not commit API keys, `.env` files, generated artifacts, caches, or local virtual environments.
- Inspect `git status` before editing and preserve unrelated user changes.
- Prefer `apply_patch` for hand-edited files and small, reviewable changes.
- Do not use destructive cleanup commands or rewrite history unless explicitly requested.
- In the final response, summarize changed files, validation performed, and any remaining limitation.
